# ADR 0006: Vector retrieval and modality-aware source representations

Status: Accepted architecture direction; model quality and operating limits remain to be measured.
Date: 2026-09-30

## Context and hypothesis

The [concept](../product/CONCEPT.md) makes creative use of verified cultural
knowledge the product goal. Text, visual material, music and other media are
potential heritage sources and output domains. The first release may use text
briefs and text answers, but a lexical-only database path would establish the
wrong retrieval contract. A falsifying test is a paraphrased Russian query that
retrieves a relevant approved passage from a vector index and never returns a
held or revoked revision, even if that revision is a nearer vector neighbor.

The earlier [lexical measurement](0005-postgres-lexical-baseline.md) compared
two PostgreSQL configurations on eight provisional labels. It measured neither
semantic search nor expert relevance. It is a retained benchmark, not the
product architecture.

## Decision

- PostgreSQL is authoritative for immutable source revisions, rights, cultural
  review, visibility, chat ownership and exact locators. It does not hold media
  bytes or serve as the vector search engine.
- Original text documents, images, audio and video live in private, content
  addressed object storage behind authorized access routes. The current local
  private volume is the development implementation of that storage boundary.
- Qdrant is the replaceable vector index. The text slice uses a multilingual
  text embedding model with an enforced snapshot and weights hash, plus a named
  text vector space. Points refer
  to segment IDs and exact revision IDs; they do not become the source of truth
  for full text, rights or citation identity.
- Ingestion produces modality-specific representations: text passages and table
  rows/cells now; OCR/layout, image regions/captions and visual embeddings,
  audio transcript/time spans and audio embeddings later. Each representation
  keeps a locator to the immutable original. A model version or chunking change
  creates a new index generation and a replayable reindex job.
- Search selects exact currently approved, scoped revision IDs in PostgreSQL,
  passes them as a Qdrant `revision_id` payload filter during vector ranking,
  then checks each returned segment against current PostgreSQL approval, scope
  and sensitivity before returning evidence or sending it to a model. The
  prefilter prevents closer held/revoked points from consuming the bounded
  candidate set; the second check closes revocation races and stale index data.
  Revocation fails closed immediately; index deletion is asynchronous cleanup. If Qdrant
  or the embedder is unavailable, grounded generation reports unavailable
  instead of silently falling back to lexical results.
- Query and content embeddings must be generated by the same compatible model
  and preprocessing version. Cross-modal retrieval requires an explicitly
  evaluated compatible embedding space; unrelated text, visual and audio
  vectors must not be compared directly.
- The PostgreSQL lexical index may remain for offline baselines and later
  evaluated hybrid retrieval. It is not the default or a substitute for vectors.
- The first internal text candidate gate is cosine similarity 0.84. It was
  tuned on eight provisional agent-labelled queries and is not a release
  threshold. Expert-labelled held-out data and claim-level support checks
  must replace it before cultural release.

## Comparable implementations and tradeoffs

[Qdrant named vectors](https://qdrant.tech/documentation/manage-data/vectors/)
support separate embedding sizes and modalities, while its
[filtering and payload indexes](https://qdrant.tech/documentation/search/filtering/)
support candidate selection. Qdrant recommends
[match-any filters](https://qdrant.tech/documentation/search/filtering/) for many
values of one field and a [UUID payload index](https://qdrant.tech/documentation/manage-data/indexing/)
for selective revision IDs. [FastEmbed](https://github.com/qdrant/fastembed)
supports local text and image inference. This resembles the product's need for
multiple searchable media representations, but those examples do not enforce
CultureChamp's exact-revision rights policy. The post-search database check is
therefore mandatory. [S3's object model](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)
illustrates the separation of file bytes and vector metadata; the storage API
choice remains open. A dedicated vector service adds an operational dependency,
model downloads, synchronization and replay costs. Those costs are preferable
to coupling all future modality indexes to the transactional schema.
The SQL-derived allowlist adds query payload and latency proportional to the
approved revision count. Measure this and batch filtered queries or change the
index representation before a large corpus exceeds Qdrant request limits; never
silently truncate the allowlist. Qdrant's filter is a ranking constraint, while
PostgreSQL remains the final authority.

## Verification and open decisions

The first implementation must prove embedding, indexing, semantic query,
authorization, revocation, citation resolution and clean Compose recovery with
synthetic sources. The same frozen queries and corpus must compare vector-only
and lexical/hybrid candidates by language, format, latency and cost. A named
expert must validate relevance and cultural support before release. Image and
audio encoders, transcription/OCR, media rights, cross-modal relevance thresholds
and output generation providers are later milestones, not claimed capabilities.

An internal, same-fixture diagnostic found recall@5 of 0.80 for Russian SQL
lexical ranking, 1.00 for page-aggregated dense retrieval after overlapping
120-word windows, and 1.00 for the dense path with the provisional 0.84 gate.
Raw dense no-evidence false-positive rate was 1.00; the tuned gate yielded 0.00
on those same three negative cases. These figures are optimistic because labels
are provisional and the gate used them for selection. They do not establish
real-world cultural accuracy.
